# hir-lang v0.4.0 — Unions, Places Evaluated Once, Keyed Generators

**A breaking 0.x revision for the gaps the Mox sketch found.** Writing the
LSF2 spec and a full PHP-compatible sketch (Mox) against HIR 0.3 showed what
lowering a real dynamic language needs and HIR could not say: union types,
compound assignment through a host operator that evaluates its place once,
the value of an assignment, keyed yields and `yield from`, a defined error for
a `match` that matches nothing, and a `not` that is either logical or bitwise
but not both. v0.4.0 adds them, picks up `pow` and PHP shifts from OPS v2,
proves that lenient validation needs at most two repair rounds, and adds
`lookup_local_in` for resolvers. The spec (`specs/HIR.md`) is revised to v3.
The body-graph view, the textual syntax, and the binary encoding remain
specified-only and land in 0.5.

## What's new in 0.4.0

### Union and intersection types

`Ty::Union` and `Ty::Intersection` cover PHP/Mox `int|string`, `A&B` and DNF
types, TypeScript, and Python. They have one **canonical form**: at least two
members, no union directly inside a union (nor a `Nullable`), members strictly
ordered by a key that ignores resolutions, so `int|string` and `string|int`
are the same HIR and resolving a name never reorders anything. Lowering builds
them in source order; `finish` normalizes them.

```rust
use hir_lang::{Builder, Name, Pat, Prim, Stmt, Ty};
use intern_lang::Interner;

let mut names = Interner::new();
let mut b = Builder::new();
let s = b.ty(Ty::Prim(Prim::Str));
let i = b.ty(Ty::Prim(Prim::I64));
let members = b.list(&[s, i]);
let union = b.ty(Ty::Union(members));
let nullable = b.ty(Ty::Nullable(union)); // string|int|null
let pat = b.pat(Pat::Wild);
let decl = b.stmt(Stmt::Let { pat, ty: Some(nullable), init: None, else_: None });
let body = b.block(&[decl], None);
let f = b.func(Name::new(names.intern("f")), &[], body);
let root = b.module(None, &[f]);
let hir = b.finish(root)?;
let Ty::Union(sorted) = *hir.ty(union) else { unreachable!() };
assert_eq!(hir.list(sorted), [i, s]); // canonical order
# Ok::<(), hir_lang::HirError>(())
```

### Places evaluated once

`$a[f()] .= "x"` must call `f` once, and `.=` is a host function in Mox, not
an OPS op. `Expr::LetPlace { binder, place, body }` evaluates the place's
operands once and names the place for reads and writes:

```text
let_place p = $a[f()] in p = mox.concat(p, "x")
```

The same form covers `??=` and the `++`/`--` templates. The alias crosses no
frame, so no execution tier needs a run-time reference object. `Assign` now
evaluates to the value it wrote, so `$a = $b = 3` works; the spec gives
bcgen-lang's lowering of both.

### Generators and errors

- `Yield { key, value }` for `yield $k => $v`, and `YieldFrom` for
  `yield from`, which forwards keys, sent values, and thrown errors and
  evaluates to the inner generator's return value.
- A `yield` inside `finally` or `defer` is now valid, following LSB rule 12;
  only yielding while the generator is being closed fails, at run time.
- A `match` with no matching arm raises `NoMatch` (E0200). Mox maps it to
  `UnhandledMatchError`.

### Ops (OPS v2)

`not` is now logical only (LSB `dlnot` on dynamic values) and `bit_not` is
the bitwise complement (`dnot`). `pow` consults the overflow policy
(`promote` gives PHP's float results), and `shift = saturate` gives PHP's
shift behaviour.

### Lenient validation in two rounds

0.3 looped up to 16 rounds and, past that, emptied the module; later-round
problems were silently treated as cascades. In 0.4 each round removes the
consequences of its own repairs before the next pass, so one round for the
node-local checks and one for the tree walk always suffice. The spec states
the argument, a debug assertion checks it under the property tests, and every
problem a pass finds is reported. An orphaned subtree is now reported once, at
its top.

### Resolver support

`Hir::lookup_local_in(path, name, ns)` finds a binder in another namespace
than the path's own, for `T::new` where `T` is a type parameter.

## Breaking changes

See the [CHANGELOG](https://github.com/jamesgober/hir-lang/blob/main/CHANGELOG.md#040---2026-10-09)
for the full list. The ones most code will meet:

| 0.3 | 0.4 |
|---|---|
| `Expr::Yield(value)` | `Expr::Yield { key: None, value }` |
| `OpKind::Not` on integers | `OpKind::BitNot` |
| exhaustive `match` on `Expr`, `Ty`, `BinderKind` | add `LetPlace`, `YieldFrom`; `Union`, `Intersection`; `Place` |
| `EffectProblem::YieldInCleanup` | removed (`yield` in cleanup is valid) |
| a union node keeps its shape | `finish` may sort it, wrap it in `Nullable`, or replace it by its only member |
| the first unreachable node in arena order | the top of the orphaned subtree |

## Verification

Run on Windows x86_64 (the coordinator runs the Linux gate):

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo +1.99 clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
```

All green, including `cargo +1.99 clippy`. Counts: 24 unit, 47 error-path, 12
resolution, 20 (0.3) feature, 20 (0.4) feature, 6 spec-example, 4 every-form, 8
depth, and 11 property tests, plus 320 doctests (every public item, `README.md`,
and `docs/API.md`). A one-off run of the property tests at 50,000 arbitrary arenas
and 20,000 generated programs passed, including the two-round assertion.

Benchmarks (`cargo bench --bench bench`, release profile, Windows x86_64,
library only):

| Benchmark | 0.3.0 | 0.4.0 |
|---|---:|---:|
| Build 825,001 nodes | ~32 ms | ~34 ms |
| Validate them | ~27 ms | ~25 ms |
| Walk them (`walk`) | ~6.7 ms | ~7.1 ms |
| Clone, compare, drop | ~15 ms | ~13 ms |
| Resolve 180,000 paths | ~1.4 ms | ~1.3 ms |
| Validate a 1,000,000-deep chain | ~44 ms | ~43 ms |
| `finish` on 100,000 unions (normalize + validate) | — | ~76 ms |
| `finish` on a 100,000-deep union nest | — | ~109 ms |

Union-free code skips normalization, so the first six rows are within run-to-run
noise of 0.3. Unions cost about 0.7 µs each (with their members).
