# hir-lang v0.3.0 — Review Fixes, While Breaking Is Cheap

**A breaking 0.x revision of the HIR data model.** An adversarial review of
0.2.0 found design gaps that every consumer would have hit: no notion of
compilation units, no partial path resolution, one user mistake rejecting a
whole unit, missing PHP/Mox forms, missing low-level forms, and a resolver
forced to re-derive the scope rules. v0.3.0 closes them before lower-lang,
resolve-lang, and typeck-lang are built on top. The spec
(`specs/HIR.md`) is revised to v2 alongside. The body-graph view, the textual
syntax, and the binary encoding remain specified-only and land in 0.5.

## What's new in 0.3.0

### Units and definitions across units

A `Hir` is one compilation unit with a host-assigned `UnitId`. Resolutions
name items and variants through `Res::Def(DefId)`, which works across units;
`Res::Extern` names host/stdlib symbols. `DefId`s minted by a builder or `Hir`
carry a private tag, so an id from a different `Hir` of the same unit is
rejected (`ForeignDef`) instead of silently pointing at the wrong item.

```rust
use hir_lang::{Builder, Def, DefId, Expr, Name, Ns, Res, UnitId};
use intern_lang::Interner;

let mut names = Interner::new();
let mut b = Builder::for_unit(UnitId::new(2));
let callee = b.name_path(Name::new(names.intern("helper")), Ns::Value);
let call = b.expr(Expr::Path(callee));
let body = b.block(&[], Some(call));
let main = b.func(Name::new(names.intern("main")), &[], body);
let root = b.module(None, &[main]);
let mut hir = b.finish(root)?;

// `helper` lives in unit 7: accepted here, checked by the host.
let helper = DefId::foreign(UnitId::new(7), Def::Item(hir_lang::ItemId::from_index(0).unwrap()));
hir.resolve(callee, Res::Def(helper))?;
assert!(hir_lang::print(&hir, &names).contains("→ item u7:0"));
# Ok::<(), hir_lang::HirError>(())
```

### Partial resolution

`Path { root, qself, res, unresolved }` follows rustc: `res` covers a prefix
and the remaining segments are resolved by type. `Vec::new`, `T::Item`,
`Self::Output`, and `<T as Add>::Output` are all expressible, and
`resolve_partial` checks the shape in O(1).

### Lenient validation

`Builder::finish_lenient` collects every problem, repairs each offending node
to its error form (or a narrower fix), suppresses the cascades a repair
causes, and returns a valid `Hir` with the problems in source order. A
`break` outside a loop or an out-of-range literal becomes a diagnostic; the
rest of the unit is still analyzed. Strict `finish` is unchanged for tools.

### Resolver support

The walk now reports `ScopeOpen`, `ScopeClose`, `Bind`, `FrameOpen`, and
`FrameClose` events (`Event` is `#[non_exhaustive]`), and `Hir::lookup_local`
returns the innermost in-scope binder by name in O(log n + d), so resolve-lang
reuses the validator's scope rule instead of re-deriving it.

### Language coverage

- **PHP/Mox:** by-reference parameters and place arguments, `$a = &$b`,
  `static`/`global` locals, `$o->$p`, `$o->$m()`, `$$name`, `$a[]`, several
  base classes, traits (`mixin` classes and `use T { … insteadof …; … as … }`),
  `protected`, `parent::`/`static::`/`self::` roots, top-level code
  (`Module.body`).
- **Python:** defaults evaluated once at definition (`DefaultEval::Once`),
  multiple bases, `Pat::Ident` for bare-name patterns.
- **Low level (Zero, Iron, Kraken):** unions, function-type ABIs, atomics
  with C++20 memory-order checks, fences, volatile access, structured inline
  assembly, a `Named` intrinsic escape hatch.
- **Generics:** associated-type bindings and constraints, region arguments
  and bounds, `impl Trait`, constants as range-pattern bounds.
- **Closures:** recursive closures via `self_binder`; parameter defaults in
  their own frame.
- **Tools:** `Builder::copy_subtree` (fresh binders for everything bound
  inside), `Hir::get_*` accessors, `Hir::all_implicit_captures`.

### Semantics corrected

- Jumps may leave `finally` (they override the pending completion); `defer`
  still forbids them.
- A `continue` inside its own loop's `step`, and `yield` inside `defer` or
  `finally`, are rejected.
- Generators can be resumed with an exception and closed; async generators
  (`ASYNC | YIELD`) are specified; the LSB mapping covers both.
- The spec no longer claims declared effects bound run-time failures; the
  body-graph design gives every fallible operation an unwind edge.

## Breaking changes

See the [CHANGELOG](https://github.com/jamesgober/hir-lang/blob/main/CHANGELOG.md#030---2026-10-08)
for the full list. The ones most code will meet:

| 0.2 | 0.3 |
|---|---|
| `Res::Item(id)` / `Res::Variant(id)` | `Res::Def(hir.def(Def::Item(id)))` / `Def::Variant` |
| `Path { segments, ns, res, global }` | `Path::new(segments, ns)` plus `root`, `qself`, `unresolved` |
| `Segment.args: List<TyId>` | `List<GenericArg>` |
| `Ty::Const(e)` | `GenericArg::Const(e)` |
| `ClassDef.base` | `ClassDef.bases` |
| `ItemKind::Module { items }` | `Module { items, body, effects }` |
| `Closure { … }` literal | `Closure { …, ..Closure::new(body) }` |
| `Pat::Range { lo: Option<Lit>, … }` | `lo: Option<PatId>` |
| exhaustive `match` on `Event` | add a wildcard arm |
| `HirError::BinderNotBound` | removed: unbound binders are valid |
| `Hir::param(id) -> Option<&Param>` | `-> &Param`; `get_param` for `Option` |

## Verification

Run on Windows x86_64 (the coordinator runs the Linux and newest-toolchain
gates):

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
```

All green. Counts: 18 unit, 47 error-path, 12 resolution, 20 feature, 5
spec-example, 4 every-form, 8 depth, and 11 property tests, plus 317
doctests (every public item, `README.md`, and `docs/API.md`).

Benchmarks (`cargo bench --bench bench`, release profile, Windows x86_64,
library only):

| Benchmark | 0.2.0 | 0.3.0 |
|---|---:|---:|
| Build 825,001 nodes | ~33 ms | ~32 ms |
| Validate them | ~26 ms | ~27 ms |
| Walk them (`walk`) | ~9.5 ms | ~6.7 ms |
| Clone, compare, drop | ~12 ms | ~15 ms |
| Resolve 180,000 paths | ~1.2 ms | ~1.4 ms |
| Validate a 1,000,000-deep chain | ~34 ms | ~44 ms |
| Walk it with `walk_from` (all events) | ~22 ms | ~26 ms |

`walk` now takes a node-only path; `walk_from` also reports scopes, binders,
and frames. The slower rows come from larger paths and more checks.
