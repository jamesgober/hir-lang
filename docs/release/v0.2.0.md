# hir-lang v0.2.0 — The Foundation of the LexerSketch HIR

**The data model, and the hard part of the roadmap.** v0.2.0 turns the
scaffold into the high-level IR that every LexerSketch language lowers into:
every node form of the spec (`specs/HIR.md`), dense arena storage with typed
ids, a builder that stamps an origin on every node, a validator that is total
and linear, in-place name resolution checked in O(1), iterative traversal, and
a deterministic debug printer. The body-graph view, the textual syntax, and the
binary encoding are specified in the same spec and land in 0.5; they are not in
this release.

## What is hir-lang?

The load-bearing wall of the LexerSketch semantic tier. Mox, Mercury, Iron,
Kraken, Zero, HQL, and NOML all lower into HIR, so resolve-lang, typeck-lang,
match-lang, capability passes (borrow-cc for Iron), the T0 evaluator, and the
lowering to ir-lang SSA are each written once. hir-lang owns the representation
and nothing else: no parsing, no name lookup policy, no type inference, no code
generation. It depends on `span-lang` 0.4 and `intern-lang` 1.

## What's new in 0.2.0

### The node forms

Items (functions with default, named, variadic, and receiver parameters;
records; sums; classes; interfaces; impls; aliases; associated types;
constants; globals; modules; imports), 30 expression forms, statements with
let-else and `defer`, 13 pattern forms, 16 optional type forms, and attributes
on any node. Every form has an error variant, so broken source still lowers.

```rust
use hir_lang::{Builder, Name, OpKind};
use intern_lang::Interner;

let mut names = Interner::new();
let mut b = Builder::new();
let (p, n) = b.local_param(Name::new(names.intern("n")));
let use_n = b.use_binder(n);
let one = b.int(1);
let sum = b.op(OpKind::Add, &[use_n, one]);
let body = b.block(&[], Some(sum));
let inc = b.func(Name::new(names.intern("inc")), &[p], body);
let root = b.module(None, &[inc]);
let hir = b.finish(root)?;
assert_eq!(
    hir_lang::print(&hir, &names),
    "(module\n  (fn inc\n    (param normal\n      (bind n%0))\n    (block\n      (op add overflow=error\n        (use (path n → local n%0))\n        (lit 1)))))"
);
# Ok::<(), hir_lang::HirError>(())
```

### Decisions the spec settles

- **One loop.** `Loop { label, body, step }`: `step` runs after each iteration
  and on `continue`, which makes `while`, C `for`, and `do-while` exact
  desugarings without rewriting bodies; `for-each` goes through each
  language's iteration protocol in its lowering template.
- **Resolution in place.** Paths carry a namespace (fixed by their parent) and
  a resolution slot. Lowering resolves its own template temporaries (hygiene by
  construction); resolve-lang fills the rest with `Hir::resolve`, checked in
  O(1) against scope intervals and frame floors the validator computed.
- **Frames.** Items, closures, and constant contexts limit what a reference may
  reach: locals cross only closures with implicit captures; type-level binders
  also cross constant contexts and impl/interface/class members.
- **Explicit captures.** PHP `use` and C++ lists bind fresh inner binders; the
  implicit capture set is derived (`implicit_captures`), never stored.
- **Ops carry exactly their policy** (OPS §2), including `promote` for Mox/PHP,
  which is rejected where HIR fixes a static result type.
- **Effects** map one-to-one onto LSB's suspendable frames (`yield`, `resume`,
  `await`, `spawn`), and the validator guarantees each effect form appears only
  in a frame that declares it.
- **D12** is resolved as option (a): a body-graph view in hir-lang (0.5), with
  an Iron ownership example showing the 0.2 model carries what it needs.

### Validation

`Builder::finish` is the only door. The validator is total (no panic on any
arena) and linear, and reports the first problem in a fixed order with one of
23 error variants (27 shape problems): dangling ids, shared or unreachable
nodes, binder misuse, namespace and resolution errors, out-of-scope and
non-capturable references, jumps without targets, misplaced effects, and op
policy mismatches.

### Tests and verification

- **Against a reference.** A property test lowers random programs while a
  recursive environment walk computes what the validator must say; the
  validator's single-pass interval algorithm agrees on the result and the exact
  first error on every case (1,024 per run; 20,000 in a one-off run).
- **Totality.** Random arenas of arbitrary nodes and ids never panic the
  validator; accepted ones walk, print, and re-validate (2,048 per run; 50,000
  in a one-off run).
- **Mutations.** Nine targeted corruptions of valid programs each yield their
  own error.
- **Depth.** ~1M-node chains of every recursive shape validate, walk, print,
  clone, compare, and drop on the default test stack.
- **Determinism.** Equal input gives equal HIRs and byte-identical printed and
  debug forms; a golden snapshot covers every node form.

## Verification

Run on Windows x86_64 (the coordinator runs the Linux and newest-toolchain
gates):

```bash
cargo fmt --all -- --check
cargo clippy --all-targets -- -D warnings
cargo clippy --all-targets --all-features -- -D warnings
cargo clippy --all-targets --no-default-features -- -D warnings
RUSTDOCFLAGS="-D warnings" cargo doc --no-deps --all-features
cargo +1.85 clippy --all-targets --all-features -- -D warnings
cargo test --all-features
cargo test --no-default-features
cargo +1.85 test --all-features
cargo bench --no-run
```

All green. Counts: 14 unit, 47 error-path, 12 resolution, 4 every-form, 8
depth, and 9 property tests, plus 259 doctests (every public item, `README.md`,
and `docs/API.md`).

Benchmarks (`cargo bench --bench bench`, release profile, Windows x86_64,
library only):

| Benchmark | Windows |
|---|---:|
| Build 825,001 nodes | ~33 ms |
| Validate them | ~26 ms |
| Walk them | ~9.5 ms |
| Resolve 180,000 paths | ~1.2 ms |
| Validate a 1,000,000-deep chain | ~34 ms |
